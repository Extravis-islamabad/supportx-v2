### 2026-11-16 — Lane B: WP-053 S1, CMDB foundation

Migration 0173 (down revision 0168, re-pointed at its queue turn) adds `cmdb_ci_types`,
`cmdb_ci_states`, `cmdb_cis`, `cmdb_ci_versions` (SELECT and INSERT only for the app) and
`cmdb_settings`, all with forced RLS; the downgrade refuses per tenant while CMDB data exists.
The new `cmdb` module follows the announcements template: API under `/api/v1/cmdb`, outbox
events, realtime, history, audit, erasure port, import-linter contract.

Choices beyond the plan, for review:

- **No CI attributes in S1** (the coordinator, after lane C's #524 review: no second
  custom-field system, §6.6). A follow-up adds a type-subtree scope to the metadata module so CIs
  (and later asset types) use metadata custom fields with field access, sealing, search and
  reports. `cmdb_cis.custom` (JSONB, GIN) is kept for them; nothing writes it yet.
- **`cmdb.manage` compatibility:** `cmdb.view` and `cmdb.manage` moved from identity_access's
  reserved list with their keys unchanged; saved grants need no data step. `cmdb.manage`
  covers add, edit and delete; the asset manager also gets the finer rights by default.
- **Field access (ADR-047):** no catalogue yet. The repo rule is that a field is offered only
  once every read path withholds it, so registering now would allow rules that do nothing.
- **No mentions port yet, so erasure waits:** CI snapshots keep the description text and the app
  cannot update them; redaction needs a definer function, as 0167 has for history. `cmdb` is in
  `REQUIRED_MENTION_PORTS`, so every report stays incomplete and approval is refused
  (`erasure_report_unavailable`) until the port lands (the coordinator, 2026-11-16).
- **Review fixes:** the CI record never remounts on someone else's save (ConflictDialog keeps the
  edit); moving to the trash and removing a type or state ask first; toasts say the outcome;
  `can_link` (picker rule for direct links), `ci_refs` returns a dict with the state category and
  the type's label key or names (lane A).
- **Event name:** `cmdb.config.changed` (the registry requires `<module>.<entity>.<action>`).
- **List filter:** `type_tree=` (a type and those below it); `type_id=` stays one type only.

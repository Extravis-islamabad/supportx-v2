### 2026-11-11 — WP-045d S4c: change data for reports and dashboards (lane A)

Migration 0143 (a reporting-role grant, lane B blocks). No new event.

- **Change report fields (REQ-CHG-116):**
  - the change source offers stage, emergency path, type, reason, risk, retrospective, freeze
    overridden (an override or the emergency CAB's pass), implementation outcome and actual
    time, and planned and actual downtime;
  - each field is a correlated subquery on the change's own rows, keyed tenant first;
  - never the plans, the risk answers or anyone's reasons in words.
- **Drill-down (AC2):**
  - a type's own fields are in the shared filter registry (`access.type_fields`), so the change
    list takes the change fields and the problem list the problem fields;
  - incidents take neither;
  - the console's drill drawer opens the change list for a change report (the report's
    `list_path`).
- **Measures:**
  - count;
  - success rate: successful (with or without issues) out of the changes whose implementation
    has an outcome. None gives no data, never 0%; RATE gained an optional `of` denominator;
  - failed or backed out;
  - emergency share and retrospective share;
  - freeze overrides;
  - average implementation time (actual times only);
  - planned and actual downtime totals.
- **Built-ins:**
  - the starter set plus 11 change reports (by stage, type, risk, reason and outcome; success
    rate by type and by group; emergency share and downtime per month; implementation time by
    type; freeze overrides by group);
  - four change key numbers;
  - the ready-made **Changes** dashboard. It is code, not a seed, so every tenant has it at
    once (AC1) and nothing needs re-running.
- **Per viewer:**
  - the dashboard list leaves out a built-in dashboard over an entity the viewer may not report
    on (permission or licence);
  - the widget catalogue already compiles each entry per viewer;
  - measures count only the changes the viewer could list.
- **Live (AC3):** report results follow the entity's list channels, as for incidents, so a
  change closing reaches the dashboard.
- **Reporting role (0143):** SELECT on `work_item_change_details`, `work_item_stage_schedules`
  and `work_item_downtimes` only. RLS still applies: with no tenant set the role reads nothing,
  and the plans stay unreadable.
- **Volume (the coordinator's check):** 100,000 changes on this Mac.
  - Every Changes dashboard widget has a median under 2 s, for the admin and for a group-scoped
    viewer.
  - Slowest: downtime per month, median 1.8 s; EXPLAIN ANALYZE execution 1.03 s.
  - The downtime subqueries use `ix_work_item_downtimes_tenant_item`; work_items is scanned for
    the year's rows, as the incident reports are.
  - The test is opt-in: `SUPPORTX_CHANGE_REPORT_SCALE_ROWS`.
- **Also:** `labels_of` is exported from work_items, for lane B's asset history.

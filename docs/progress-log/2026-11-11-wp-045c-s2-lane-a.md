### 2026-11-11 — WP-045c S2: a change's schedule, conflicts and freeze override on screen (lane A)

No migration. Builds on #376 (S1).

- **Schedule tab (`ChangeSchedule.tsx`):**
  - the conflicts panel lists each conflict's kind, the window or "another change", the time,
    and whether it blocks. It is live through the record and the windows' broadcast;
  - the implementation window is editable, with the stage row's If-Match. A window that sends
    approved stages back asks first (`reapproval-preview` with the window);
  - planned and actual downtimes are added and removed (the read-only Downtime tab is gone);
  - each stage's dates follow, as before.
- **A save in a blocking freeze:**
  - it says why (`errors.change_window_blocked`);
  - for holders of `changes.override_freeze`, a "Go ahead anyway" dialog takes a reason and
    passes **only the freezes the 409 named** (`window_ids`, as lane B's #376 review set). The
    save is then tried again;
  - without the permission there is no button, and the server refuses anyway.
- **Announce a planned downtime:** for those with `announcements.manage`, this opens the new
  announcement form prefilled through router state, never the URL: a title, a warning severity,
  "until" the downtime's end, and a body naming the window. It stays a draft until someone
  publishes it.
- **Labels** in en, ar and ur, including plurals for the counts.
- **Tests:** `schedule.test.tsx` (4): conflicts; the refusal without the override; the override
  naming only the refused freeze and the save retried with If-Match; announcing a downtime.

# 2026-11-16 — WP-057 S3b-2a: sensitive custom fields sealed at rest (lane C)

- **Migration 0171:** `work_item_field_index` (RLS, tenant-first indexes, FK cascade, digest
  check), `custom_fields.seal_state` and `seal_cursor`. The downgrade refuses while any tenant has
  index rows or non-plain fields.
- **Writes:** `custom_values.seal_custom` seals sensitive values under `work_items/custom` bound to
  the record and field, keeps them out of `custom_text`, and upserts the blind index. A sealed value
  sent back unchanged keeps its stored ciphertext, so it records no change.
- **Reads:** `visible_custom` / `visible_custom_many` strip ADR-047's hidden and masked fields, then
  open the rest. Unreadable values come back empty and are listed in `unreadable_fields`. The guard
  test `tests/test_custom_values_guard.py` holds every reader to this.
- **Lists:** `list_query`'s `rewrite_for` hook turns `eq`/`in` on a sealed key into an EXISTS over
  the index. Other operators are refused (`field_not_filterable_sealed`, en/ar/ur), sealed keys
  never sort, and withheld fields are never rewritten.
- **History:** sealed per cell (`field_changes`, record, `<type>:<field>@v<n>:<side>`) on create,
  update and automation. Moved to another cell, a value does not open.
- **Reports** withhold non-plain fields. **Erasure mentions** open sealed values in memory, seal
  them again on redaction, and log admin passages (AUD-017 `erasure_passage`, en/ar/ur).
- **Tests:** blind-digest unit tests; `tests/db/test_sealed_custom_fields.py` (4 pass); migrations
  and guard (13 pass); the guard test (3 pass).
- **Left for S3b-2b:** the re-seal job and the `sensitive` switch.

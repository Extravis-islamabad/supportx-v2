# D-115 (2026-10-29)

## Decision

**WP-025 plan decisions** (SLA v1 on Temporal; approved by the coordinator for the product owner, 2026-10-29). (D1) **4 sessions**, not 3: Temporal infrastructure is a session of its own. (D2) **Default working week: Monday-Friday 09:00-18:00** in the time zone of the tenant's default site, with three presets offered in one click at setup and in the onboarding checklist (Monday-Friday 09:00-18:00, Sunday-Thursday 08:00-17:00, Monday-Saturday 09:00-18:00); never guessed from a country (file 03 question 4). **Priority change: open targets are recalculated from the SLA start** (Appendix A); "restart from the change" is a tenant setting; a target already past breaches at once with reason `target_changed`, so reports can separate it; met and breached stamps never change; a due date set by hand is not moved (file 03 question 5). (D3) Sites and support groups store their `calendar_id` (organization's own data); organization checks it **only through the sla module's public interface**, and "calendar in use" is answered through organization's public interface. (D4) **ADR-037** (SLA clocks: Temporal as the waker, PostgreSQL as the truth), numbered at commit time. (D5) A **60-second safety net** fires anything over 2 minutes late through the same exactly-once path. (D6) An **in-memory evaluator for the shared filter DSL** in `app/shared/api/filters`, held to the SQL compiler by a property test. (D7) **Targets and levels are snapshotted when an SLA is applied**: editing a policy never rewrites running records (REQ-SLA-031 AC1 early); "re-apply to open records" stays V1. (D8) A record resolved with no public reply has its response target **"met at resolution"**, labelled, and shown as its own state in SLA reports. (D11) A new permission **`incidents.edit_due_dates`**, granted by default to admins and group leads, not technicians (least privilege). (D12) Escalation recipients not yet in the data (**site manager**, **change manager**) are not offered until those fields exist; assignee, group lead, assignee's manager, requester's manager and department head are. **Approved by the product owner (2026-10-29):** (D9) **`tzdata`** (Apache-2.0, checked on PyPI 2026-10-29, version 2026.6) so `zoneinfo` works in every image and the Nuitka build, and **`icalendar`** (BSD-2-Clause, checked on PyPI 2026-10-29, version 7.3.0) for holiday and working-calendar import instead of an own parser; imported files are untrusted, so the import keeps size and line limits and has a fuzz test. Everything `icalendar` brings (PyPI metadata, 2026-10-29): `python-dateutil` (Apache-2.0 and BSD-3-Clause, dual), `six` (MIT) and `typing-extensions` on Python < 3.13 (PSF-2.0, permissive, not MIT/BSD/Apache), all **already shipped** through approved packages (aioboto3/botocore, pydantic and others); `tzdata` has no dependencies. New to what ships: `icalendar` and `tzdata` only. (D10) The SLA load test runs **100,000 running clocks on the single-node profile and 1,000,000 on SaaS**, in GitHub only (a scheduled workflow), never on a developer machine; REQ-SLA-037 AC3 reads with these sizes.

## Rationale

The WP-025 plan; D-074 says defaults are decided in each WP plan.

# D-088 (2026-10-27)

## Decision

**WP-026 review answers (D-087):** asset/CI lookups wait for their modules: approved. List columns and export of custom fields in WP-020d: approved. Removing a field in use after a confirmation: approved, with **Retire as the recommended (primary) button and Remove as the secondary one**. **CHANGED: index requests do not wait for the next deploy.** A background **index worker** (`workers.custom_field_indexes`, its own Deployment, the only process besides the migrate Job that holds the migrator role) picks up pending requests every 30 seconds and builds them with CREATE INDEX CONCURRENTLY (writes go on), one at a time under an advisory lock. The admin screen shows **pending, building, active or failed with the reason** (timed out, table busy, disk full, out of memory, value too large, unexpected), live, and a failed index can be asked for again. The deploy's migrate Job runs the same pass as a fallback. Also: the 2 skipped backend tests are the opt-in volume and load checks (`test_audit_log_at_volume`, `test_parallel_uploads_stream_with_flat_memory`); nothing to fix.

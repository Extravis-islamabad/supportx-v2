# D-038 (2026-10-24)

## Decision

**WP-014 deployment decisions** (plan of 2026-10-24): (1) PostgreSQL through CloudNativePG with its **built-in backups** (Barman Cloud to S3-compatible storage); replaces pgBackRest in D-004. (2) **Gateway API with Traefik**, plain **Ingress** as a supported fallback (customers may bring their own load balancer). (3) **One host with paths**: console `/`, portal `/portal/`, API `/api`, realtime `/connection` and `/emulation`, Keycloak `/auth`. (4) On-prem monitoring is **permissive only** (VictoriaMetrics, VictoriaLogs, Jaeger, Perses); Grafana only inside Extravis's SaaS. (5) **SeaweedFS** is the on-prem object store (ADR-012); MinIO stays dev-only. (6) Images go to **GHCR as private packages only**; while the repo is public CI builds without pushing. No image is ever published publicly. (7) cosign signing with a **password-protected key in GitHub secrets** for now; it **moves to a KMS before the first customer release**. (8) Images are **plain CPython for now, labelled INTERNAL/DEV** (`com.extravis.supportx.distribution=internal-dev-only`); **Nuitka is required before any customer bundle** (ADR-009). (9) **k3s v1.36.5-k3s1** pinned for k3d and the appliance. (10) Components approved as D-037. (11) **Temporal later**, with the first workflow module. (12) Docker Desktop memory raised to 12 GB on the dev Mac. (13) WP-014 split into **014 / 014b / 014c / 014d**.

## Rationale

Product owner review of the WP-014 plan.

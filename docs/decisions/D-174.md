# D-174 (2026-11-17)

## Decision

**picomatch's ReDoS advisory is accepted for dev and build tools only, for 14 days** (Haider, the
product owner, through the coordinator).

- **Ignore only GHSA-fc5q-39xc-vjpf.** It's picomatch ≤4.0.7, high, a ReDoS on crafted extglobs, with no patched release. The reason recorded with it: dev and build tools only, patterns from our own config, not in any shipped image or bundle.
- **It expires on 2026-12-01** and is re-checked every Monday. It's removed as soon as a fixed picomatch ships; Dependabot will propose it. After that date the frontend audit fails while the entry is still there.
- **A CI check proves picomatch is never shipped,** so the ignore can never cover a production use:
  - the production dependency graph (the one the frontend bundle is built from) must not contain it; this runs in Security on every PR;
  - the CycloneDX SBOM of the backend, worker and web images must not list it; this runs in the cluster workflow.
- **Every other high or critical advisory still fails the build.**
- **The mobile app (2026-11-18):** Trivy finds the same flaw (CVE-2026-112366) in picomatch 2.3.2 in `mobile/pnpm-lock.yaml`. There it comes with expo/metro build tooling, and it *is* in the mobile production dependency graph.
  - Haider accepted it in `.trivyignore.yaml`, scoped to that lockfile, expiring 2026-12-01.
  - Lane B's next PR adds a check that bundles the app with Metro and fails if picomatch is in the output. If it is, the entry is removed and the dependency is fixed (an upgrade or override) before any mobile release.
- **minimatch 7.x to 11.0.0 (GHSA-g3hv-75wg-m249) is fixed, not ignored:** a pnpm override lifts it to the patched 11.0.1+.

## Update 2026-11-23: the GHSA was withdrawn

GitHub withdrew GHSA-fc5q-39xc-vjpf on 2026-11-18. Lane B's Monday re-check found that
`pnpm audit --audit-level high` is clean without the ignore. So the ignore was removed, along with
its expiry check, which narrows this decision. `make audit-frontend` now fails if
`frontend/pnpm-workspace.yaml` ignores any advisory: an ignore needs a new decision.

The same flaw under its CVE ID (CVE-2026-112366) is **not** withdrawn, and still has no fixed
release. The mobile entry in `.trivyignore.yaml` stays, expiring 2026-12-01; the coordinator is
asking Haider whether to extend it. The checks that picomatch is in no shipped image or mobile
bundle stay too. Re-checked every Monday.

## Rationale

The advisory turned Security red on every PR, but there is no fixed picomatch release to move to. picomatch reaches only vite, tinyglobby/fdir and typescript-eslint, working on glob patterns from the repo's own config, never on user input, and nothing in production depends on it (`pnpm why picomatch --prod` is empty).

Accepting it narrowly, with an expiry and a check that it stays out of what ships, unblocks the work without hiding a production risk.

## Affected docs

`frontend/pnpm-workspace.yaml` (`overrides`, `auditConfig.ignoreGhsas`); the Makefile (`audit-frontend`, `not-shipped-check`); `.github/workflows/security.yml`; `.github/workflows/cluster.yml`; `.trivyignore.yaml` (mobile).

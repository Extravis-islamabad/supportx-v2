# D-158 (2026-11-05)

## Decision

**The mobile app is built from the SupportX mobile prototype, as one role-based app** (the
product owner, 2026-11-05; first written as D-139, then D-146, then D-155; renumbered because main or another lane took those numbers; prototype: the "SupportX Mobile Prototype" design canvas, technician
and requester screens).

1. **One app for everyone, by role.**
   - Technicians and admins see Home (KPIs, a MonetX alert card, "needs your attention"),
     Queue (mine, my group, unassigned, overdue), Approvals, Alerts and Me.
   - Requesters see Home (report, catalog, announcements), Report a problem (with knowledge
     suggestions), the catalog, and My requests (status timeline, "it's fixed" / "still
     broken").
   - The same sign-in serves both. Requester-only people get portal sessions and never the
     console (D-129, ADR-044).
2. **Order:** sign-in first (WP-M2), so that every screen after it uses real data. Then the
   technician screens, the requester screens, and push.
3. The prototype's own visual style (soft lilac page, white cards, purple primary) is the mobile
   look, built on the shared tokens. Parity rule: original design, nothing copied.

## Rationale

The backend already serves almost every screen: incidents and counters, the conversation,
approvals, notifications, availability, the portal, the catalog, knowledge and announcements.
What was missing was the mobile sign-in and, later, device registration for push. One app means
one sign-in, one store listing and one release to sign.

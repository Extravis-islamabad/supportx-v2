# D-148 (2026-11-09)

## Decision

**httpcore is approved as a direct backend dependency** (the product owner, directly, 2026-11-09;
WP-048b S2).

- `httpcore` (BSD-3-Clause), pinned `>=1.0.9,<2`: the range httpx 0.28 needs (`httpcore==1.*`),
  so the two always resolve together.
- Used by the guarded outbound HTTP client (`app/shared/egress`, ADR-043 §8), which pins each
  connection to its checked IP through an httpcore network backend while TLS verifies the host
  name.
- Listed in CLAUDE.md §3's approved additions. `make licence-check` stays green.

## Rationale

The client must connect to the address it checked, never a second DNS answer (DNS rebinding):
httpx's own transport layer (httpcore) is the one place to pin the connection. It was already in
the lock through httpx; naming it as a direct dependency keeps the dependency rule (CLAUDE.md §3)
honest, so it can be reviewed and vetoed like any other.

## Affected docs

CLAUDE.md §3 (approved additions), backend/pyproject.toml and uv.lock, ADR-043 §8.

# D-118 (2026-10-29)

## Decision

**WP-040: Active Directory and LDAP through Keycloak's user federation** (product owner, 2026-10-29; plan ~/Desktop/wp-040-plan.md decision 1). On-prem installs connect to AD/LDAP through the tenant realm's LDAP user federation, configured by SupportX through the Keycloak admin API: LDAPS by default, plain only by an audited admin choice. Keycloak handles directory sign-in (REQ-SEC-012) and the user and group import; SupportX reads the result and applies the same attribute and group mapping as the Entra sync. No new LDAP library, and SupportX never handles directory passwords (the bind credential is kept in SupportX's secrets store and given to Keycloak). The rest of the plan's decisions were approved by the coordinator the same day: a separate least-privilege Entra app for sync (`User.Read.All`, `GroupMember.Read.All`), defaults editable per tenant (sync every 30 minutes, rotation reminder at 180 days, errors kept 90 days, failing after 3 runs or at once on an authentication failure), mailboxes moving into the connector catalogue by expand/contract with `mailbox.failing` kept as an alias, and lane A's "needs reassignment" view fed by `identity_access.user.status_changed` (new defaulted fields `reason`, `source`). The number is rechecked against main at merge (D-117 is lane C's).

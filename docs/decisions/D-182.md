# D-182 (2026-11-23)

## Decision

**The mobile Trivy ignore for picomatch's CVE-2026-112366 is extended by 14 days, to
2026-12-15, on the same terms as D-174** (Haider, the product owner, through the coordinator).

- It is scoped to `mobile/pnpm-lock.yaml` in `.trivyignore.yaml`, as before.
- The same checks keep it honest: the Cluster workflow's SBOM step (picomatch in no shipped
  image) and #540's Metro bundle check (picomatch in no mobile bundle).
- It is re-checked every Monday, and removed as soon as a fixed picomatch ships or the CVE is
  withdrawn.
- The frontend's pnpm ignore for GHSA-fc5q-39xc-vjpf is removed (lane B's re-check,
  2026-11-23): GitHub
  withdrew that advisory on 2026-11-18, and `pnpm audit` is clean without it. `make audit-frontend`
  now fails if the workspace ignores any advisory. The CVE itself is not withdrawn.

- At the time of this decision, Trivy 0.76.1 with a fresh database no longer reports
  CVE-2026-112366 at any severity in `mobile/pnpm-lock.yaml`, even without the ignore. Its
  database seems to have followed the GHSA withdrawal. The entry stays as Haider decided, in case
  the CVE comes back. The next Monday re-check proposes removing it if Trivy still doesn't report
  it.

## Rationale

D-174's ignore expires on 2026-12-01, and there is still no fixed picomatch release (the latest
is 4.0.7). The facts it rests on haven't changed: build tooling only, and nothing shipped
contains it. Letting it lapse would turn Security red on every PR, with nothing to upgrade to.

## Affected docs

`.trivyignore.yaml`; `frontend/pnpm-workspace.yaml`; the Makefile (`audit-frontend`).

# D-124 (2026-11-02)

## Decision

**Console UI pass: one dense, consistent layout for every console screen** (product owner,
through the coordinator, 2026-11-02; plan ~/Desktop/ui-pass-plan.md, lane C, #159). The design is
original on Ant Design 5 and copies no other product's screens, wording or icons (CLAUDE.md §2).
(1) **Density:** the console uses Ant Design's compact algorithm under light, dark and high
contrast: controls 28 px, table rows 40 px, type 12/13/14/16/18/20 (meta, data, body, section,
record, page), spacing 4 · 8 · 12 · 16 · 24 · 32 only (`packages/ui/src/density.ts`). The portal
keeps the default density. Urdu keeps its taller line height; rows grow rather than clip.
(2) **Shared layout components** in `packages/ui/src/layout/`, used by every module:
`PageHeader` (one per page: title, count, back, at most three page actions, description; level 2
inside a page that owns the h1), `ListPage` + `FilterBar` (view · search · quick filters ·
"Filters (n)" · columns) + `FiltersDrawer` (every other filter), `RecordPage` (header, action
bar, tabs and a 320 px properties panel that stays on every tab and folds into one "Properties"
section below 992 px), `RecordHeader`, `PropertiesPanel`, `AlertStrip` (one alert, or
"N alerts · View" that expands in place) and `KpiTile`. The rules are written up in
docs/architecture/console-design.md.
(3) **Action bar (updates REQ-WI-010):** buttons show only the actions available now, at most
four, the most useful ones by rank; they sit in the record's fixed order and the best-ranked one
is primary. "More actions" lists every action in one fixed order, unavailable ones disabled with
their reason; destructive actions come last after a divider and ask before running. With a
read-only licence every action is disabled with the read-only reason. Tabs stay fixed
(REQ-WI-011).
(4) **Navigation:** the side menu with labels (208 px) is the default, icons only (64 px) a
per-user choice. Migration 0051 changes the default and moves every existing user from the top
bar to the side menu once; the product owner approved this for the pre-pilot dev, QA and demo
data only (CLAUDE.md rule 5h). **After go-live a changed default never overwrites a preference
a user has stored:** only users without a stored choice get the new default.
(5) **Demo tenant:** `make demo-seed` fills the tenant with the slug `demo` only, idempotently,
through the modules' services (RLS, events and history apply); its password comes from the
environment, never a repository file. QA and e2e data stay in their own tenants.

## Rationale

Screens built module by module had grown different headers, toolbars, spacing and action rows,
and looked loose next to the products customers compare SupportX with. One set of components
and tokens makes every screen alike and denser, and keeps the rules testable: the components
carry their own tests, and the screens keep their test ids.

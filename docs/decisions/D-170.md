# D-170 (2026-11-13)

## Decision

**An approximate sign-in place from the DB-IP Lite city database, read with `maxminddb`** (Haider,
the product owner, through the coordinator, for WP-057 S2b; lane C builds it).

1. **What it shows.** Sessions and the sign-in log name where a sign-in came from, roughly:
   - **a mapped site:** an address range an admin mapped to a site (10.1.0.0/16 = Islamabad HQ),
     internal or public, with the most specific range winning;
   - **"Internal network":** private, loopback, link-local, IPv6 unique-local and carrier-grade
     NAT addresses, never a guessed city;
   - **a city and country:** otherwise, from the database.
2. **The database.** DB-IP Lite city (CC BY 4.0) with the `maxminddb` reader (Apache-2.0), both
   approved additions (CLAUDE.md §3). The file (about 126 MB) is never in an image:
   - it is a separate artifact in the offline update bundle and a mounted volume, refreshed
     monthly through the mirror;
   - admins see the date it was built;
   - DB-IP is credited on the About dialog.
3. **The site map is tenant data:** the tenant's own sites, edited by identity managers, and
   audited.

## Rationale

People and admins need to tell a familiar sign-in from a strange one (REQ-SEC-030, REQ-SEC-033)
without SupportX sending addresses to an outside service. A local database works the same on
SaaS, on-prem and air-gapped installs. An internal address is never given a city, because a
guess there would only mislead.

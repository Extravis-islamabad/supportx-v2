# D-111 (2026-10-28)

## Decision

**WP-020d defaults** (plan ~/Desktop/wp-020de-plan.md, approved 2026-10-28; defaults approved 2026-10-28 with a change to (3)). (1) Columns: the list starts with the columns it had before (D1); a user's columns, widths, sort and page size are saved per view (`work_item_list_settings`), never for anyone else or another view; any list field can be a column, custom fields included; a column of a removed custom field drops out. (2) New built-in views: overdue and due today (open records by their resolution due time), followed by me, shared with me (a follow that grants access, D-068), from my direct reports (open records whose requester's manager is me). "Pending approval" waits for WP-030 and the type filter for service requests (WP-031). (3) Saved views hold the list API's own filter and sort; private, shared with chosen support groups, or shared with everyone who sees incidents (product owner: same pattern as dashboards); only the owner changes or removes one. The builder offers one group (all/any) and leaves people fields out (the "my …" views cover them). (4) Time range on created, updated, due or resolved; presets today, this week, last 7 days, this month, this quarter (exact in the user's time zone) and a custom range. (5) Search chips on status, status category, priority, group, site, category, impact, urgency, channel and level; the same field twice means either value; the earlier priority and custom-field quick filters stay. (6) Page size 25, 50 (default) or 100. (7) Bulk: up to 1,000 records, frozen when asked for ("all N" is the list's own query); run by the consumers worker (picked up within 5 s, batches of 50) as the requester, so every record's permissions, transitions, closure rules and open-work checks apply and a refusing record is skipped with the reason; bulk edit offers impact, urgency, priority (with a reason), category, level and site; assigning away from yourself needs an explicit tick; resolve and close send a resolution or closure code only when given, so records without one are skipped (REQ-INC-120 AC1); history names the job (`field_changes.batch_id`); jobs are visible to their requester only; lists refresh once per batch. (8) Export: the list's records through lane C's report export; a built-in view travels as its filter equivalent, and "updated by others" (not expressible as a filter) says it cannot be exported; the file has the list's columns and sort (lane C's #108); needs the reports.export permission.

# D-099 (2026-10-27)

## Decision

**Password reset and invitations: Keycloak's own emails for MVP, done properly** (WP-039 session 2). The person sets their password on Keycloak's pages; **passwords never pass through SupportX** (authentication.md unchanged). (1) **One place to configure mail:** SupportX writes the Keycloak realm's SMTP settings from the same installation mail settings as the mail foundation (`app/shared/mail`), so on single-tenant on-prem (D-070) these emails come from the customer's own sender. (2) **Keycloak's email theme is branded like the login theme:** tenant logo, name and colours, texts in en/ar/ur, matching SupportX's own emails. (3) **Invitations use the same path** (Keycloak's update-password and organization invitation emails), triggered by SupportX, with the invitation recorded and audited in SupportX. (4) **SaaS multi-tenant (WP-014d): revisit with an ADR**: a SupportX password page (passwords through the admin API, policy enforced by Keycloak) or a per-tenant sender via Keycloak; added to WP-014d in mvp-build-plan.md.

## Rationale

Product owner answer to the WP-039 session 2 question (how a person sets their password after a tenant-branded link).

# D-122 (2026-11-02)

## Decision

**Speed mode until the MVP** (product owner, through the coordinator: "I want development faster"; only 6 of the last 48 hours went to building). (1) Required checks are the fast ones only: `backend` (checks, three test shards and the coverage gate), `frontend`, `pre-commit`, `chart`, `dependency audit (pip-audit, pnpm audit)`, `filesystem scan (Trivy)`, `secret scan (gitleaks)`; `core profile, integration and e2e` is no longer required (the product owner changed the ruleset; the queue groups up to 5 PRs and waits 1 minute). (2) The heavy jobs (core stack with integration and e2e, cluster images with Trivy and SBOM, the k3d smoke test, the PDF tests in the worker image, worker resilience) run nightly on main, on a manual run, and on a pull request labelled `full-ci`; never in the merge queue. (3) No CI or Security run on push to main: the merge queue tested that exact merge commit (merge method "merge"). CI and Security run nightly. (4) `full-ci` goes on risky PRs only: migrations that touch existing data; security, authentication or tenant isolation; cross-module changes. (5) A red nightly is the owning lane's first task the next morning, and nothing else merges in that area until it is green. (6) One PR per work package, no stacked PRs; small fixes go into the current work package's PR or the lane's weekly polish PR. (7) The full gate, e2e included, becomes required again before the pilot (WP-043). Rule 5 of the work cycle stays: security, isolation, data-loss and silent-failure tests run on every PR in the backend suite.

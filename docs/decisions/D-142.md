# D-142 (2026-11-05)

## Decision

**Remote access and the device agent are SupportX's own; AgentX is dropped entirely** (WP-050,
WP-051; the product owner, through the coordinator, 2026-11-05; components approved the same day).

- AgentX is no longer used, neither its remote control nor its data format.
- **User devices:** attended remote control on MeshCentral (Apache-2.0), fully rebranded as
  SupportX, self-hosted and working offline, started from the incident and the asset ("Remote
  session").
- **Servers:** RDP, SSH and VNC in the browser through Apache Guacamole (Apache-2.0), rebranded.
- **One SupportX Agent per device**, one package, doing both inventory and remote assistance. Its
  core and the site probe are written in **Go**. MeshAgent (C, Apache-2.0) is built from source and
  rebranded inside that one package, keeping every licence and NOTICE attribution in the
  third-party notices.
- **Libraries:** go-ldap, masterzen/winrm, golang.org/x/crypto/ssh and gosnmp. Agentless Windows
  scanning needs WinRM enabled (for example by group policy), and the docs say so.
- **Server side:** the MeshCentral server and Guacamole run from pinned, scanned images with an
  SBOM, using a one-time pass flow, and are off unless remote access is switched on.
- **Security, unchanged:** the end user approves every session and sees a banner they can end it
  from; a permission plus MFA; audited and linked to the incident; optional recording; time
  limits; a tenant switch to turn remote access off. No AGPL component (so no RustDesk).
- **Code signing:** a Windows OV certificate (not EV) and an Apple Developer ID (organisation),
  bought later, before the first customer agent release. Dev and CI use test signing with the keys
  kept offline.
- **Push relay:** optional and off by default, never for air-gapped or sovereign installs, with the
  data it carries limited; Android uses a self-hosted ntfy.

## Rationale

One agent and one server-side stack that Extravis controls work the same on SaaS, on-prem and
air-gapped, and keep the product's branding and licences under its own control. MeshCentral and
Guacamole are mature, Apache-2.0 and self-hostable, so remote access needs no cloud service and
no AGPL code.

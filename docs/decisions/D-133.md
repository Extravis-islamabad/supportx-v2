# D-133 (2026-11-04)

## Decision

**WP-030 D3: the catalog's edition split** (product owner, through the coordinator, 2026-11-04;
approves the default as built).

- **Essentials (`service_request`):** service requests from catalog items: categories and items,
  forms, one approval stage (approvers by name or the requested-for person's manager, backup and
  fallback), the item's SLA, group and technician, an ordered fulfilment plan, the portal's
  requests and approvals.
- **Professional (`catalog`):** the advanced catalog: multi-stage, parallel and conditional
  approvals, costs, bundles, item versions and the rest of REQ-CAT that needs them.

Always through the entitlement interface (`has_feature`), never a deployment check (CLAUDE.md 5f).

## Rationale

Every tenant that has service requests needs the basics to raise and fulfil one; the advanced
parts matter to larger catalogs and go with the higher edition, as in the parity notes (file 02,
question 1).

# D-109 (2026-10-28)

## Decision

**WP-024 email channel defaults** (plan ~/Desktop/wp-024-plan.md; approved by the product owner 2026-10-28 with (2) and (9) as below; the number is rechecked against main at merge). (1) **Mailboxes live in the `integrations` module** (§6.1); outgoing mail stays in the one sender, `app.shared.mail` (D-089). Records are made through the inbound port (`app.shared.mail.ports`), which work_items implements for incidents. (2) **IMAP first** (TLS by default, STARTTLS allowed). Microsoft Graph and the Gmail API come in session 2. Their OAuth apps are registered once per installation by the customer, in the customer's own Microsoft or Google admin console, so on-prem mail never passes through an Extravis app (product owner). The step-by-step admin guide is docs/guides/mail-oauth-apps.md. (3) **Fetching:** every 2 minutes per mailbox. A message changes on the mail server only after SupportX has stored it, and it is marked read by default: never deleted unless the admin chooses that. A ledger per mailbox and Message-ID makes a message count once. A mailbox that cannot be read shows "failing" with the reason on Admin › Mail. (4) **Unknown senders:** by default only senders from the mailbox's allowed domains become requesters (who cannot sign in). Other senders get a polite answer and nothing is created. Automatic mail is never answered. (5) **Loops and floods:** mail from our own addresses is never processed. A sender's 11th message within an hour, and any message over 35 MB, is held for an admin. (6) **Replies:** a reply finds its record by the subject token ("[INC-12]", now on every notification e-mail) or, failing that, by the notification it answers (In-Reply-To/References against the delivery log). Only the requester (or the person it is for) adds a public reply. Staff and others are held as "not the requester", by agreement with lane A. The quoted history is not kept. (7) **Out-of-office on a record:** recorded as an automatic entry, with no reaction and no notification. (8) **Security:** a connection without encryption is refused unless the admin allows it explicitly (audited). Mailbox passwords are sealed with the installation key ring (the files key ring), bound to the tenant and purpose, and never returned. (9) **Held mail is never invisible:** Admin › Mail has a review queue (MVP, product owner) listing each held message with its reason. An admin can release it (handled again, with the reason overridden where that is safe) or discard it (kept in the ledger as discarded).

# D-168 (2026-11-13)

## Decision

**Security paths are code-owned by a separate reviewer account** (Haider, the product owner,
through the coordinator; lane B builds it).

1. **The reviewer account:** Haider creates a free GitHub account, `supportx-reviewer`, which lane
   B uses to approve security pull requests. Haider sets up its sign-in himself; no session,
   script or file ever handles the account's token or password.
2. **CODEOWNERS:** `.github/CODEOWNERS` names `@supportx-reviewer` for a tight, mostly file-level
   list: sign-in, sessions and tokens (identity BFF, session cipher and store, OIDC, API keys,
   MFA, SSO, password reset, service identities, the Keycloak admin client); the policy layer,
   roles, every module's permission catalogue and every module's `api/` folder (where routes
   declare permissions), with `main.py` and the module registry; tenant isolation
   (`core/tenancy.py`, `shared/db/rls.py`, `migrations/helpers.py`, the RLS guard and the
   migrations guard test); settings, middleware, trusted proxies and rate limits; the shared
   crypto, egress and files packages; the audit and licensing modules; the secrets script, network
   policies, Keycloak files and identity tooling; `security.yml`, `.semgrep.yml` and `CODEOWNERS`
   itself. No test folders in general, no `ci.yml` or `cluster.yml`. Nothing else is owned: this
   **supersedes D-007's catch-all** (`* @devhat-pm`). Every lane pushes as that account, which
   can't approve its own PRs, so with code-owner review on every PR would block (the coordinator,
   for Haider, 2026-11-13).
3. **Required:** Haider turns on "Require review from code owners" in the `main` ruleset once the
   account exists.
4. **Migrations (option (b)):** CREATE/ALTER/DROP POLICY, GRANT and REVOKE reach migrations only
   through the owned `migrations/helpers.py`; `backend/tests/test_migration_policy_sql.py` fails
   on such SQL in any other migration. The merged migrations that already hold it are a fixed list
   in the test, as merged migrations are never edited (CLAUDE.md §6).

## Rationale

- One mistake in these files can let one tenant read another's data or let someone sign in who
  shouldn't. A required review by a named security reviewer, only on those paths, catches that
  without slowing every other pull request.
- Owning every migration would put nearly every work package behind the security review. Keeping
  the access SQL in owned helpers protects the part that matters with a plain, strict test.

## Affected docs

.github/CODEOWNERS, docs/dev-setup.md (Security code owners), docs/architecture/tenancy.md (Adding
a new tenant-scoped table), backend/tests/test_migration_policy_sql.py.

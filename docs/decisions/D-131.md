# D-131 (2026-11-04)

## Decision

**Local AI models, swappable models, and AI conversation retention** (WP-037/038; the product
owner's answers to Q1, Q2 and Q3, through the coordinator, 2026-11-04).

- **Q1 + Q2 approved:** the local runtimes are vLLM and the llama.cpp server. The models are
  Qwen3-14B (chat), Qwen3-4B (small chat, development and small installations) and bge-m3
  (embeddings). Their licences allow on-prem redistribution. Weights ship as installer artefacts,
  never in a container image.
- **Quantised to one GPU:** Qwen3-14B runs quantised so it fits one 24 GB GPU. WP-037 states
  the quantisation used and the quality measured with the eval set at that quantisation
  (session 2, local runtime).
- **Swappable by configuration only:** `SUPPORTX_AI_MODEL`, `SUPPORTX_AI_EMBEDDING_MODEL` and
  `SUPPORTX_AI_BASE_URL` choose the model; no code names one. Some government and bank customers
  may refuse a Chinese-origin model (Qwen and bge-m3 both are), so the guide names a non-Chinese
  alternative per role that works with the same configuration: Mistral Small 3.1 24B Instruct
  for chat and multilingual-e5-large for embeddings (docs/guides/ai-models.md). A test proves a
  differently configured model name is the one the gateway calls, answers with and logs.
- **Q3 approved, retention:** AI conversation text is kept 30 days by default, adjustable by
  admins per tenant (AI settings). It is **never used for training**, which the docs and the AI
  settings screen both say. Every deletion is audited: the retention purge (`ai.calls_purged`,
  with the count and the period) and erasure of a person (`ai.calls_erased`). Any manual deletion
  added later must be audited too.
- **On developer Macs:** never a large model in Docker. Use the small native model or the recorded
  fake. CI always uses the recorded fake.
- Possible-duplicates packaging (its own entitlement key, on in every edition) and the other
  overnight choices stand as built.
- **Applied in WP-037 session 2 (2026-11-04):**
  - **One embedding width, 1024.** The embedding store (`ai_embeddings`, migration 0075) needs
    one fixed vector width for its HNSW index. Both approved embedding models, bge-m3 and
    multilingual-e5-large, are 1024 wide, so swapping between them stays a configuration change.
    A model of another width is refused (it is never stored), and needs a migration that widens
    the column first.
  - **Vectors of two models never meet.** Every row records the model and width that made it. A
    search compares only the configured model's vectors. After a model change, an hourly job
    re-embeds the old rows through each owning module's text source, so results are never mixed
    or wrong while it catches up.
  - **Quantisation and quality**, measured with the eval set (`make ai-eval`, docs/guides/ai-models.md):
    - Development: Qwen3-4B Q4_K_M with bge-m3 Q8_0.
    - Qwen3-14B: Q4_K_M for demos on a Mac (`make ai-demo-model`), AWQ on the GPU node (vLLM, one
      24 GB GPU). It is measured at the first demo switch; this Mac cannot hold it while the
      lanes run.

## Rationale

Local AI is a product pillar (sovereign, on-prem and air-gapped). The approved models are
multilingual (English, Arabic, Urdu) and fit the hardware customers have. Swapping by
configuration keeps the product sellable where a model's origin is a procurement issue. Retention
and audit answer the privacy questions customers ask first.

# D-180 (2026-11-20)

## Decision

**A vendor support session sees people's names by default and never their e-mail address or
phone. A grant can tick "Mask names too"; then names are withheld as well.**

Haider's answers to parked items 16-18, given through the coordinator.

- **Names are shown by default.** A support engineer sees the requester's and staff's names, so
  they can follow a record's history.
- **E-mail and phone are always withheld** from every support session, whatever the grant says.
  `unmask_personal` no longer reveals them. It still governs the tenant's *other* personal custom
  fields (masked unless the grant unmasks them), as before.
- **A per-grant "Mask names too" tick** for the customer admin, off by default and audited. It is
  a new grant column (migration 0188) in its own PR after #566; lane B blocks it. With it ticked,
  names show as the labelled stand-in and person search is refused.
- **Mentions follow the names setting:** when a grant masks names, mention chips show the same
  stand-in.
- **Person search** for a support session matches the **display name only**, in the query itself:
  never the e-mail, username, phone or employee number. Typing an address, its local part or its
  domain finds nobody. With names masked, search is refused (`person_search_masked`). One helper
  (`identity_access/service/person_search.py`) decides this for every path: the people
  directory, pickers, `people_matching` and record search by person (the coordinator's and lane
  B's conditions).
- **Known limitation:** a name typed into free text (a description, a comment) is not detected or
  masked. The vendor support user guide says so.

## Rationale

The engineer needs names to understand a record, while addresses and phone numbers are the data
that would let them contact or identify people outside the system. A tenant that wants more can
tick "Mask names too" per grant.

## Affected docs

`docs/user-guide` (vendor support); `backend/app/core/tenancy.py` (`mask_contacts`,
`mask_names`); `identity_access/service/masking.py`, `person_search.py`; the `/auth/me` support
block (`names_masked`). Replaces D-173's "contacts and names masked unless unmasked" for names
and contacts.

# D-151 (2026-11-09)

## Decision

**A dev-only quick sign-in for the showcase personas**, so browser-driving QA (Claude in Chrome)
signs in without typing passwords (the product owner, through the coordinator, 2026-11-09).

- **The page:** `/dev/sign-in` on the local console and portal shows one button per Showcase
  Company persona: administrator, technician, team lead, approver, requester, and a new starter.
- **Only the local stack:**
  - it is on only when `make dev-quick-sign-in` sets `SUPPORTX_DEV_QUICK_SIGN_IN`;
  - it works only for the showcase tenant, and only from a loopback address with a localhost
    Host header and an Origin from the same address;
  - anywhere else its routes answer 404.
- **Never in production:** the API refuses to start with it, or with the persona secrets, under
  any profile but dev, and the Helm chart refuses to render if anything would set it.
- **The normal sign-in path:**
  - The BFF signs the persona in through Keycloak's password grant, then the usual session code
    takes over, so sessions, the MFA policy, revocation and logout behave as normal, with no
    special token.
  - The password grant is on only in the dev realm file. The base realm the chart ships, and the
    dev realm as the chart renders it, have it off.
- **Two-step sign-in stays on for the showcase tenant** (the product owner):
  - Every persona but the new starter has a TOTP authenticator, enrolled by the showcase seed from
    a key in the dev `.env`. The key is never committed, printed or logged.
  - The server completes the second step inside the same guarded path, never sending a code
    twice, because a wrong code counts toward the account's lock.
  - The new starter has none and signs in the normal way, so QA can test setting up two-step
    sign-in.
- **Audited:** every quick sign-in is recorded as `session.quick_sign_in`, with who, which
  persona and the client address.
- **Sessions:** the dev realm keeps Keycloak's session for 7 days with "remember me". The
  showcase tenant's own limits are the longest the caps allow: a day idle and a week in all. The
  global 24-hour idle cap is kept (coordinator).

## Rationale

QA as each persona in a real browser needs many sign-ins a day. Typing passwords and codes is slow
for an automated browser, and keeping them in its prompts would spread them. A one-click sign-in
that still goes through Keycloak and the normal session tests the real product. Fencing it to the
local stack in three independent places (configuration, chart and request checks) keeps it out of
every real installation.

## Affected docs

docs/dev-setup.md ("Quick sign-in for QA"); deploy/compose/.env.example; the Makefile
(`dev-quick-sign-in`); deploy/helm/supportx/files/keycloak/dev/supportx-realm.json and
backend/tooling/keycloak_realm.py.

# D-138 (2026-11-04)

## Decision

**WP-031 D13: the starter catalog** (product owner, through the coordinator, 2026-11-04).

- **What a new tenant starts with:** 6 categories and 14 items in SupportX's own words (never
  ManageEngine's sample text):
  - Accounts and access: New user account, Access to an application, Password or MFA reset
    help, VPN / remote access.
  - Hardware: New laptop, Monitor, keyboard or mouse, Mobile phone.
  - Software: Install software, Shared mailbox or distribution list.
  - Workplace: Desk or room move, Building access card.
  - People and HR: Employment letter, New joiner (onboarding), also shown under Accounts and
    access.
  - Leaving the organisation: Someone is leaving.

  The text is in `backend/app/modules/service_catalog/domain/starter.py`.
- **Approvals:** manager approval (of the person the request is for) where it fits. On VPN /
  remote access it is on by default, because remote access is a security-sensitive grant; a
  tenant removes it on the item if it wants to.
- **Password or MFA reset help:** a service request with no approval and quick fulfilment
  (priority P2). Its description points to self-service first ("Forgot password?" and the help
  article), shown before the form.
- **New joiner (onboarding):** one request, with manager approval. It creates the account,
  laptop and access tasks, then a first-day welcome.
- **Languages:** English, Arabic (Modern Standard Arabic) and Urdu for every text. Arabic and
  Urdu are flagged for native-speaker review in `docs/guides/urdu-review.md`.
- **Seeded as drafts.** An item is published only with a fulfilment group (WP-031 plan D9), and
  a new tenant has none. The admin catalog shows "starter items: choose a group and publish",
  with one action that is audited and publishes only the items whose checks pass. The seed
  creates no group.
- **When it is seeded:**
  - **New tenants:** on the new `organization.tenant.provisioned` event, through the outbox, by
    an idempotent consumer. A per-tenant marker (`catalog_settings.starter_seeded_at`) makes it
    happen at most once, so a tenant that deletes everything never gets it back.
  - **Existing tenants:** migration 0074 marked every tenant that existed before, so none is
    seeded automatically.
  - **Existing dev, QA and demo tenants:** `make catalog-starter TENANT=<slug>` seeds only an
    empty catalog. The showcase seed uses it and publishes the items with its service desk
    group.
  - Not on first read: a GET never writes.

## Rationale

New tenants get a useful catalog in their languages on day one without any data the tenant did
not ask for (a group, published items without a fulfilment team). Event-driven seeding keeps
audit and outbox ordering, and the marker makes retried provisioning safe.

## Affected docs

WP-031 plan, PROGRESS.md, docs/guides/urdu-review.md, PR #200. Tenant provisioning, when it is
built, must emit `organization.tenant.provisioned` once the tenant is ready (lane B noted it).

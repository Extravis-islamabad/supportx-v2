# D-161 (2026-11-11)

## Decision

**Field encryption (WP-057) reuses the files key ring: per-tenant data keys wrapped by an
installation key, behind one key-provider interface.** Haider (product owner) chose option A,
through the coordinator, 2026-11-11. Lane C builds it in WP-057.

1. **Envelope encryption.** Each tenant has its own data keys. Field values are encrypted with
   them (AES-256-GCM, the PyCA `cryptography` already approved by D-021). The data keys are
   stored only wrapped by an **installation key**, and every wrapped key carries a **key ID**,
   as the files key ring does.
2. **Where the installation key lives.**
   - On-prem and air-gapped installs: a Kubernetes Secret.
   - SaaS: a cloud KMS, reached through External Secrets Operator (D-037/D-038).
   - Code reaches it only through **one key-provider interface**. No deployment-mode branch exists
     in domain or service code (rule 5f).
3. **Customer-managed keys later.** A customer's own KMS or HSM is another implementation of the
   same interface. It is not built now.
4. **Rotation re-wraps the data keys only.** A new installation key re-wraps the tenant data keys
   under a new key ID. Encrypted field values are not rewritten. The old key ID is kept until no
   data key uses it.
5. **First users:** the fields named in the WP-057 hand-over. These include webhook header values
   in workflow definitions, which #406 masks on every read but stores in plain text until WP-057
   (lane B's review of #406).

Not part of this decision: making the **sign-in session key rotatable** (key IDs for the session
encryption of D-021). Haider wants that too, and it is lane B's work, recorded separately.

## Rationale

- One key ring for files and fields: one rotation story, one audit trail, and one place the
  installation key lives on every deployment.
- Wrapping per-tenant data keys keeps rotation cheap, because only small wrapped keys are
  rewritten and the data stays as it is. It also keeps a later per-tenant or customer-managed key
  a matter of swapping the provider.
